Starting this month, I'm grouping these into one running post per month instead of a separate entry for every small change — easier to follow than a stream of one-liners, and less pressure to write something every time a feature ships. Here's what moved this September.

## IntentFlow

Two smaller additions, both born out of just using the app myself.

**Weekly Goals now has two types.** The original version only handled one shape of goal well: tally toward a weekly target, like "Run 3×." That's fine for habits you're counting, but it never fit something like tracking my weight — there's no weekly target to hit, just a number that changes over time and that I want to see trend. So Weekly Goals now offers a **Counter** (the original behavior) and a **Tracker**: log a value on any day, no target, no weekly reset, just an accumulating history. Tap the trend icon on any tracker and you get a chart of the last 30 entries plus the full dated list. Existing goals didn't need any migration — anything without a type is just treated as a Counter, same as always.

**The app can now reopen to whichever tab you were last on.** Landing preference already let you pick a fixed tab to always open to, which is genuinely useful for a habit like always checking Today first. But I found myself wanting the opposite just as often — I'd be deep in Plans, close the app, and land back on Today needing to tap back over. Now there's a "Last tab used" option alongside the fixed choices, so both habits are supported rather than picking one at the expense of the other.

Neither of these needed a redesign — both slotted into decisions already made earlier (the Plans tab already remembers your last-selected list the same way; the sync work already required tracking "what tab were you on" for its own reload logic).

**The brand-new-install demo content now matches the walkthrough post I wrote about the app.** I wanted to be able to open a fresh device, narrate that post as a script, and have the app already showing the exact habits, goals, and events it describes — instead of generic placeholders that don't line up with what I'm saying. So the default habits, Weekly Goals, and events a new install seeds itself with are now the same ones the walkthrough talks through, and Plans ships with two lists built from the walkthrough's own examples: a Plan-mode weekend-trip itinerary and a Priority-mode apartment-hunting checklist, sorted by the same Impact/Urgency/Effort scoring the app actually uses. The old generic "Ideas of lists" checklist is still there too, just moved to the end, so nothing that existed before quietly disappeared. None of this touches anyone's real data — it only ever fills in on a genuinely empty install. Alongside that, the "Weekly Goals & Trackers" section got a small wording tweak to "Weekly Goals / Trackers," and the Plans mode menu now lists Plan above Priority, matching the order I actually introduce them in the walkthrough.

**The Today tab then went through several more rounds of tightening**, mostly from just using the app myself with a habit list that had grown longer than the one I designed against. Weekly Goals / Trackers and Due Today now sit *above* the daily habit list instead of below it, so both stay visible with no scrolling or collapsing once the habit list gets long. Habits gained their own **▾** collapse toggle for the whole section, and — since checking things off during the day was still leaving a shrinking set of unchecked habits buried under a growing set of checked ones — a habit you've done today now hides itself by default, with a "Show completed" toggle to bring it back (useful for editing one you've already checked off). A couple of smaller layout passes followed the same reasoning: on habit rows, the done-circle and edit-pencil swapped sides so the one you tap constantly sits on the easier, one-handed-reachable side and the rare one sits on the other; the same logic moved each Weekly Goal/Tracker card's log button to its trailing edge; and those cards can now be dragged into whatever order actually matters to you, via a grip on the left. Last, the score card itself shrank — the habit/chore/goal breakdown line and the small five-day bar chart both felt like they were duplicating what the score history screen already shows, so both are gone, and the score number just sits, a little smaller, right next to the button that opens that history.

Two smaller renames rode along with that work: the **Events** tab is now **Upcoming** — it's a browsable schedule list, not a reminder feed, and "Events" was a name left over from before Calendar split out into its own tab — and each row there now shows its type/recurrence label next to the item's name, with the date moved into a colored pill on the right, which reads more naturally at a glance than the old layout.

## Shop

Shop — the grocery and household tracker — got two updates as well.

**Sync is now automatic**, carrying over the same approach IntentFlow got a few weeks back. Once signed in, a device backs itself up shortly after any change and quietly pulls in newer data whenever the app is opened — no more remembering to tap Backup or Restore. The one moment that still asks first: a device with its own local data signing in to an account that already has a backup somewhere else. Everything after that first decision happens silently in the background.

**Others list items can now be dragged to reorder**, using the same grip-handle pattern the Stores tab already had — so groceries stay grouped by category as before, but the miscellaneous Others list can finally be arranged however makes sense to you.

Small compounding benefit of building things with reusable patterns instead of one-off logic each time.

**Shop can also now be packaged as an actual Android app**, ahead of putting it on the Play Store. It's still the same web app under the hood — no rewrite — wrapped in a Trusted Web Activity so it opens full-screen with no Chrome address bar, the way an installed app should. Getting there surfaced one genuinely useful side-finding: the packaging tool couldn't fetch the app's own icons because a bot-protection setting on the domain was blocking it, which is likely the same reason an earlier Google review flagged the app's home page as looking like it was "behind a login page" to an automated crawler. Turning that setting off fixed both. The remaining steps — the actual Play Store listing, screenshots, and submission — are on me to finish outside of any code change.

## Delete safety

The one change that touched every part of both apps at once: routine deletes now show an "Undo" action right on the confirmation toast instead of asking "are you sure?" beforehand. I'd been going back and forth between a few options — confirm-before-delete, undo-after-delete, or swipe-to-delete — and landed on undo-after for the everyday, one-item deletes (a habit, a grocery item, a link, a plan step): a dialog you have to click through on every single delete stops being a safety net and just becomes reflex, while a few seconds to tap Undo actually gets read. Deleting something bigger — a whole Plans list, a store's saved card, everything in a list at once — still asks first, since those are rare enough that the friction is worth it. IntentFlow already had a snapshot-based undo tucked away in Settings, so this mostly meant surfacing it right where the action happens; Shop didn't have anything like it, so it got a matching one built from scratch, plus a half-finished version of the same idea I found sitting unused in the code got properly wired up instead of left dormant.

## Privacy & Google sign-in

The other real thread this month didn't touch either app's day-to-day features, but I think it matters as much as anything else: both apps now have an actual privacy policy, written in plain language, plus a short line right at the "Sign in with Google" button so it's clear in the moment what that button does — not buried three taps deep in Settings.

That work turned up a small discovery I hadn't expected. Both apps' Google sign-in runs through the same Google Cloud project behind the scenes — deliberate, so I wouldn't have to get the app reviewed by Google twice — which meant the Privacy Policy link Google itself shows *during* sign-in was pointing at Shop's page even when you were signing into IntentFlow. Easy to miss, since it only shows up on Google's own screen, never in the app. Fixed by giving both apps a shared page at yeahvibe.com that covers sign-in in general, with each app's own page one click deeper for the specifics.

Then I actually put both apps through Google's real verification process, to get rid of the "unverified app" warning testers see when signing in. Genuinely useful, if slow: Google's reviewers came back with specific, itemized feedback on the privacy page — spell out exactly what data is accessed, how it's used, who it's shared with, how it's protected, how long it's kept — and answering each point explicitly made the policy better, not just more compliant. Worth doing even with just a couple of testers.

## Plans, rebuilt as an actual tab

The single biggest change of the month, and the one that took the most direct back-and-forth to get right. Plans had been a dropdown-plus-popup since the start — pick a list from a `<select>`, see its contents inline below it. I asked for something closer to a real app screen: "I would like these to be displayed in a full tab view as opposed to a popup today. In this full tab view, one would be able to reorder, rename, or edit, and also add sections. One could press a button to all plans, pick a plan to dive into it, and possibly go back to the list of plans with a return button... It would also be useful if sections could be added in the Links tab. And they share similar design."

That's exactly what shipped. Plans is now two real screens: an **all-plans list**, where every plan is its own row — tap to open it, rename in place, drag to reorder, group plans under optional section headers — and a **plan detail screen** for whichever one you opened, with its own back button (and, on Android, the phone's own back gesture) to return to the list. Whichever screen, and whichever plan, you last had open is where the tab lands next time, so it behaves like a real drill-down rather than resetting every time you switch tabs. Links got the identical treatment — sections, drag-and-carry, the same visual language — since the request was explicit that both should share one design.

The very first version of this shipped with a few rough edges, surfaced immediately by real feedback: "I miss some of the template plans. also no option for sections. I also prefer delete button on the left of the screen, and reorder on the right." All three got fixed the same day — the demo template plans came back, section support was extended to Plans' own all-plans screen (it had only shipped for Links at first), and delete/reorder swapped sides to match the request. A separate, genuinely nasty bug also turned up around the same time: under the right conditions a real plan could silently vanish from the all-plans list despite still existing in storage, because the screen trusted a cached order array instead of actually checking what was on disk. Fixed by making the list scan for every real plan directly rather than trusting a potentially-stale index — plans can't go missing from the screen that way anymore.

From there, Plans and Links both kept gaining small, real capabilities through the rest of the month: a **▾** collapse toggle for sections — rolled out first to the all-plans screen and Links, then (after a screenshot made clear "sections" and the in-plan "Parts" headings look identical to a user even though they're different things under the hood) extended to a single plan's own Day 1/Day 2-style parts too; the collapse toggle on a part's header was later moved to sit next to the part's name instead of next to its delete button, after enough near-mistaps; and most recently, each plan's own **⋯** menu gained a **Duplicate** option (clones a whole plan, content and all, right after the original) and its existing "Copy list" button now reads **"Extract plan"** specifically in Plan mode, since that's already exactly what it did — copy the full thing to the clipboard as text — just under a name that didn't make that obvious.

## Both apps, now real Android apps

IntentFlow and ShopTools are both now also installable as proper native Android apps, not just home-screen PWAs — a deliberate step up from ShopTools' earlier Play Store attempt (a Trusted Web Activity, which renders through the real Chrome app and shares its storage) to a Capacitor-based wrapper for each app, with its own fully isolated storage. Both point at the live site rather than bundling a copy, so a normal web update reaches native users the same way it reaches everyone else — no app-store release needed except for native-only changes like the icon or permissions.

The one real native-specific wrinkle: Google refuses to render its own sign-in page inside any app's embedded browser component, as an anti-phishing measure. So inside both native apps, Google sign-in opens in a real Chrome tab instead, and getting back into the app afterward relies on a verified link between the app and its domain — a small file published on each site that proves the app is allowed to claim that domain, which is what lets Android hand control back to the app instead of leaving the sign-in stuck open in the browser. Both are now confirmed working end-to-end, including after a very specific Samsung-phone wrinkle where ShopTools' old TWA build and its new Capacitor replacement were both trying to claim the same domain on the same test device — only one toggle, buried in Android's own per-app settings, actually needed switching off.

ShopTools is now also partway through an actual Play Store submission — a signed release build, Play Console app, and an Internal testing upload are all done; a four-way hunt for the *right* signing certificate to list (Google re-signs the app with its own key before real users ever see it, and the page that shows that fingerprint turned out to label it inconsistently) was this month's most "I did not expect to spend an afternoon on this" moment, but it's resolved. What's left before real testers can get in is store-listing paperwork rather than anything left to build: screenshots, the content rating questionnaire, and the Data Safety form.

## ShopTools becomes an actual name for what it does

Shop had quietly outgrown its own name. What started as a grocery list had already picked up a general Inventory tab (any kind of stock, not just groceries), Stores and loyalty cards, a Links tab, and — this month — a real Budget tab, after a conversation that started as "merge my separate budgeting app into Shop" and ended somewhere more useful: a Budget tab built fresh inside Shop itself, covering recurring income and expenses, a computed monthly leftover, and a running daily spending log against it, rather than migrating a whole separate app's data over. The rename to **ShopTools** happened alongside that, since "Shop" stopped describing what the app actually did the moment budgeting joined groceries, inventory, stores, and links under one roof.

Budget kept growing from there: it now supports **multiple named budgets** (Food, Pocket money, whatever split makes sense), not just one, using the same all-budgets-list-then-drill-in pattern Inventory already used — deliberately reusing a shape users had already learned rather than inventing a new one. Expenses can be grouped into named, collapsible subsections (with their own running totals), items can be dragged from one subsection straight into another, and a subsection can now be created without needing to add an expense to it first.

A full audit pass went through every tab afterward, checking that everything could actually be edited, reordered, and deleted — not assumed, actually checked function by function — which turned up and fixed six real gaps (inventories list had no reorder, categories couldn't be renamed or deleted in two different tabs, recurring income rows had no reorder, expense reorder broke with no subsections defined, and spending-log entries couldn't be edited after the fact, only deleted and re-added). The Android app's hardware back button was also wired up properly across every sheet and modal, since until this month it only closed the one screen that happened to push its own browser history entry — everything else fell straight through to exiting the app.

## Both apps now teach themselves

IntentFlow picked up an animated guided tour — a spotlight overlay that highlights real, live buttons and tabs in sequence rather than a separate video or set of screenshots, offered as a genuine choice on first open ("show me around" vs. skip) and replayable anytime from Settings. It started as a six-step walkthrough, then grew to ten after a direct follow-up asked for it to cover Today's own sub-sections (Weekly Goals, Due Today, habits) and the AI-assist feature specifically, rather than treating Today as one single stop. ShopTools got the identical treatment days later, adapted to its own five tabs rather than a literal copy.

Both apps' Settings panels got decluttered around the same time — ShopTools dropped a five-paragraph, ~750-word "how this app works" block entirely once the tour covered the same ground interactively, on the reasoning that explaining the app twice in two different places wasn't actually helping anyone.

## Smaller things that add up

**AI-assisted add**, inside both apps, got meaningfully better this month. Typing a rough description into any Add form and tapping the small ✨ button sends it to a shared backend that classifies it and prefills the rest of the form — date, time, frequency — for review before saving; it stopped switching which form was open out from under you if it mis-classified ambiguous text, and started being told which form was actually open so it can weight a genuinely ambiguous phrase toward what you can actually see. A standalone top-level "Ask AI" entry point that used to exist alongside this was removed outright once the inline version covered the same job better.

**Sync got quietly more solid underneath**, in both apps, without changing anything you'd notice day to day: the conflict check that stops one device's backup from silently overwriting another's moved from a client-side fetch-then-compare-then-save (a real, if small, race window) to a single server-side function that does the whole check-and-write in one step. ShopTools actually had *no* conflict check at all before this — every backup blindly overwrote whatever was there — so this closed a real gap, not just a theoretical one.

**IntentFlow picked up an integrated Quick Timer** (start/pause/reset, presets, an alert on completion — the same countdown mode from the standalone QuickTimer app, built in) that's gone through two homes this month: first tucked into the Today tab's habits section, then moved up into the header next to Settings after feedback that it was easier to reach from there regardless of which tab you're on.

A long tail of smaller, real fixes rounded out the month on both apps: a voice-dictation duplication bug, a reminder scheduler that could silently miss its one 30-second check on a throttled background tab, `localStorage` writes that failed silently when a device's storage filled up, a habit/weekly-goal icon field that fought with the keyboard, a Weekly Goal Tracker that now pre-fills with the last logged value instead of a blank field (so nudging a weight by one digit doesn't mean retyping the whole number), and a genuinely subtle CSS specificity bug where a collapse toggle looked like it was working — the class was flipping correctly — while the browser quietly ignored it because a different, later style rule happened to win the tie.
